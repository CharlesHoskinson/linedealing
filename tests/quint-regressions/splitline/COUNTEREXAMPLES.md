# Split-line Quint findings and their counterexamples

Each finding of the split-line models (`formal/quint/splitline.qnt`, `formal/quint/splitline_pools.qnt`, `formal/quint/splitline_birth.qnt`, `formal/quint/splitline_binding.qnt`) is checked against real arithmetic or against a scripted replay of the model.
The verdicts are CONFIRMED (the counterexample works under the old rule), NOT REPRODUCED, GUARD HOLDS (the design rule stops it) and OPEN DESIGN.
Run the arithmetic with `python3 design/enhancement/vectors/quint_counterexamples.py`.
Run the replays with the `quint test` commands below, from `formal/quint`.

Item 11 replays every trace of this directory on the prototype reducer (`impl/tests/quint_split_replay.rs`, adapters in `impl/tests/itf_split/`). The test `every_trace_is_replayed_or_excused` lists the seven traces it cannot express and why: the four recovery-through-E traces (no recovery transition), `rt_m_leafset` (an actor rule, covered in `ecdsa.rs`), `w5_mutant` (node disks; the witness quorum test is `w5_five_acks_are_refused_at_n9`) and `wk_design` (WK1, covered in `split_state.rs`). Every mutant trace is refused, or its mutated effect is absent from the reducer.

The ITF traces in this directory replay each scenario. A file named `pt_<instance>__<run>.itf.json` comes from the run of the same name in `formal/quint/splitline_pools_test.qnt`.
The `Broken` runs pass only on the mutant instance and fail on `pt_design` at the step that reuses the slot. The `Holds` runs pass on the design instance.

The sampled runs of the mutants `pm_window`, `pm_no_window_burn`, `pm_reshare_no_anchor` and `pm_reshare_all` reach no violation in 20,000 traces of 80 steps, because each attack needs about fifteen specific steps in order. The scripted runs W1, W3, R1 and R2 kill them. The scripted run of each mutant passes, and the same run fails on the design instance (job `neg_pt_design_broken` in `formal/quint/runs/split/jobs.txt`).

`g5_prototype_counterexample.rs` holds the two regression tests of G5 (`impl/tests/g5_prototype_counterexample.rs` includes it). On wt-proto 7953331 they were the prototype counterexample; item 11 adopts DECISIONS 54 in `impl/` and inverts their asserts.


The sampled jobs of the splitline mutants `m_burn`, `m_precedence`, `m_distinct`, `m_bf_p2`, `m_inclusion`, `m_no_collect`, `m_cold_old` and `m_hold0`, and the fork runs `q1_sl_n7_b3` and `q1_sl_n9_b5`, found no violation in 25 steps from `init` (400 samples) or in the 7200 s limit. Each now has a deterministic run in `formal/quint/splitline_test.qnt` (modules `mt_m_*`, `q1_n7_b3`, `q1_n9_b5`) that reaches the violation on the mutant and fails on the design instance (`mt_design`). The mutant `m_witkey` is different. A witness keeps one entry per key and refuses an entry whose key holds another digest, so `C13_WitnessKeyUnambiguous` cannot fail in the model. With colliding keys the witnesses refuse a legitimate second release instead: `witkeyReleaseHolds` passes on `wk_design` and fails on `wk_m_witkey`.
