# split-request oracle (Lean 4)

`SplitRequest/Spec.lean` is the executable reference semantics of the OpenSpec
capability `split-request`
(`openspec/changes/add-split-line-dealing/specs/split-request/spec.md`, RQ-001
to RQ-074, revision 4 with DECISIONS 59 to 64). It has two parts:

* the request state machine: the board record of every request, changed by
  board events (`reqStep` for one request, `step` and `apply` for the state);
* the honest committee node: `nodeAct` gives the messages, votes, posts and
  refusals of one node for one request from the board record and the node's
  local view.

| Module | Holds |
|---|---|
| `SplitRequest/Spec.lean` | `Params`, `Req`, `Ctx`, `St`, `init`, `Op`, `Obs`, `Refusal`, `reqStep`, `step`, `apply`, `runOps`, `run`, `reqInv`, `validState`, `stepRefusals`, `paramRefusals`, `View`, `Act`, `nodeAct`, the first theorems |
| `SplitRequest/Inv.lean` | `reqStep_inv`: every accepted event keeps a request in `reqInv`, one lemma per event |
| `SplitRequest/Theorems.lean` | `run_reqInv` and the claims (C6, C7, C8, C9, C11, C20) |
| `SplitRequest/Tests.lean` | pins from the scenarios (`decide +kernel` and `#guard`), witnesses |
| `SplitRequest/Audit.lean` | `#print axioms` of every theorem and `#audit_ns SplitRequest`, pinned (generated by `../scripts/gen_audit.py`) |
| `Main.lean` | the codec only, through `../codec` |

Build and gates (from `formal/lean-split`, under `heavy-run`):

    (cd request && lake build --wfail)
    ./gates.sh oracle request
    ./gates.sh trace request

## Modes

Default: one `kink-implementation/1` request with `inputs = {"params": {"n",
"f", "delta_c", "delta_hold", "mode"}, "epochs": [{"e", "n", "f"}], "ops"}`.
Parameters or epochs outside RQ-001 give `{"end": "could-not-apply",
"reason": "outside-capability"}`. Otherwise the answer is `{"end": "final",
"cells": {"state", "obs"}}` with one observation per operation. A refused
operation is the observation `{"refused": CODES}` and changes nothing; the run
goes on.

`--step`: JSON Lines. `{"state", "op"}` gives `{"state", "obs"}`;
`{"node": {"state", "eid", "view"}}` gives `{"acts": [...]}`. A refused
operation gives `{"refused": CODES}`; a state outside `validState` gives
`{"refused": ["outside-state-domain"]}`; a line that does not decode gives
`{"error": TEXT}`.

Board events (`"op"`): `post`, `order`, `open`, `complaint`, `frame`,
`detach`, `vote_opened`, `vote_admit`, `obs2`, `release`, `post_final`,
`post_void`, `tick`, `rotate`, `land_checkpoint`, `restart_burn`, `confirm`,
`carry`, `host_fee`. Observations: `ok`, `phase` (the phase of the named
request after the event), `refused`.

Node acts: `header_partial`, `ack`, `complaint`, `vote_opened`, `vote_admit`,
`post_void` (with the reason), `release` (`g`, `j`: the partials leave the node),
`release_record` (`g`, `j`: NON_TEE, the RELEASE in the node's board vote), `failure_evidence`,
`post_final`, `sign_leaf` (with the outcome), `erase`, `handoff`, `refuse`
(with the code).

## Claims

| Claim | Theorem | Statement |
|---|---|---|
| C6 (RQ-024, RQ-030) | `C6_release_in_force` | an honest node releases only for an ADMITTED request whose authorization it reads in force |
| C7 (RQ-032, RQ-033, RQ-059) | `C7_no_release_after_revocation`, `C7_hold_p2` | a release needs a Midnight read at least as new as every OBS report with no revocation at or below it, and for P2 generation 1 the `Δ_hold` blocks |
| C8 (RQ-008) | `C8_sealed_until_order` | an honest node sends nothing for a request that is not ordered |
| C9 (RQ-030, RQ-058) | `C9_release_only_anchor` | an honest node releases only the variant the board anchored for that generation |
| C11 (RQ-051, RQ-052, RQ-054, RQ-069) | `C11_released_never_void`, `C11_held_leaf_stable`, `rq069_send_after_record` | in every run a request that released, or that a restart ended, never settles VOID; once Midnight holds the leaf no event changes the outcome; a NON_TEE node sends partials only after its RELEASE committed |
| C20 (RQ-047, RQ-057, RQ-071, RQ-073) | `C20_no_release_before_admission`, `C20_stalled_releases_nothing`, `rq073_no_stalled_after_release`, `rq071_mixed_reads_none` | in every run no request holds an anchor or a release before ADMITTED; a node that posts VOID STALLED releases nothing; a request with a committed RELEASE never has reason STALLED; MIXED never reads as STALLED |
| C13 (RQ-063) | exception, `witness_C13_final` | liveness is not a state property; the witness shows an honest run reaching FINAL |

`run_reqInv` carries the board invariants to every run from `init`:
`reqStep_inv` (one lemma per event), `expire_inv` and `newReq_inv`. The
node claims hold for every view, since `nodeAct` is a function of the
board record and the view.

These are the state parts of the claims. The cryptographic parts (shares,
partials, the combined signature, the sealed contributions) are outside the
oracle.

## Abstractions

* Cryptographic outcomes (share check, header open, release check, the
  contribution equation) and the facts of other capabilities (authorization
  in force or refused, revocation height, slot judge, acks, slot bind) are
  fields of the node's view.
* The host chain enters as a fee median per host height (`host_fee`) and a
  confirmation fact per request (`confirm`).
* Midnight holds a request's settlement leaf when a landed checkpoint covers
  its end (`end_height ≤ cp_height`) or a reissue carried it (`carry`).
* The selection rule of DESIGN §4.6 (by reference from RQ-027): the first
  variant whose fee rate meets the anchored median, else variant `K`.
