# split-envelope oracle (Lean 4)

`SplitEnvelope/Spec.lean` is the executable reference semantics of the OpenSpec
capability `split-envelope`
(`openspec/changes/add-split-line-dealing/specs/split-envelope/spec.md`, EN-001
to EN-023, revision 4 with DECISIONS 62). The state is one committee node's view before order: the current
epochs, the board height and the outer-dealing digests of the envelopes it
accepted.

| Module | Holds |
|---|---|
| `SplitEnvelope/Spec.lean` | `St`, `init`, `Op`, `Obs`, `Refusal`, `publicRefusals` (EN-004 to EN-008, EN-023 `windowBad`), `headerFaults` (EN-009 to EN-013), `combine` (EN-014), `bodyLabels`, `ticketCount`, `apply`, `runOps`, `validState`, `stepRefusals`, the theorems |
| `SplitEnvelope/Tests.lean` | pins from the scenarios (`decide +kernel` and `#guard`), witnesses |
| `SplitEnvelope/Audit.lean` | `#print axioms` of every theorem and `#audit_ns SplitEnvelope`, pinned (generated by `../scripts/gen_audit.py`) |
| `Main.lean` | the codec only, through `../codec` |

Build and gates (from `formal/lean-split`, under `heavy-run`):

    (cd envelope && lake build --wfail)
    ./gates.sh oracle envelope
    ./gates.sh trace envelope

## Modes

Default: one `kink-implementation/1` request with `inputs = {"params": {"mode", "delta_c"},
"height", "epochs", "ops"}`. The answer is `{"end": "final", "cells": {"state",
"obs"}}` with one observation per operation. A refused operation is the
observation `{"refused": CODES}` and changes nothing; the run goes on.

`--step`: JSON Lines `{"state", "op"}` to `{"state", "obs"}`; a refused
operation gives `{"refused": CODES}`; a state outside `validState` gives
`{"refused": ["outside-state-domain"]}`; a line that does not decode gives
`{"error": TEXT}`.

Operations (`"op"`): `submit` (an envelope: the public checks), `tick` (board
height), `set_epochs` (the current epochs with key-list hashes), `order_check` (`exp`
and the ordering block's `height`: EN-023 again, no state), `header` (the
checks after order, no state), `combine` (`t` partials and the fallback, no
state). Observations: `accepted` (the `eid`), `refused`, `ok`, `faults` (the
requirement IDs a header fails), `combined` (`opened`, `need_more`,
`dealer_fault`).

public checks that fail together return every code, sorted (ledger 1).

## Claims

| Claim | Theorem | Statement |
|---|---|---|
| C9 (EN-008) | `C9_run_dd_unique` | in every run from `init`, the accepted `(epoch, dd)` pairs are distinct, so no two accepted envelopes of one epoch share PRF keys |
| C10 (EN-002, EN-022) | `C10_public_checks_blind` | the public checks are a function of the public view; the request type and `body_0` do not change the answer |
| C21 (EN-002, EN-018, EN-022) | `C21_run_blind` | two runs whose envelopes differ only in their request types give the same states and observations |

These are the state parts of the claims. The cryptographic parts (the AEAD
hides `body_0`, the frame is padded, the PRF keys of distinct `dd` are
independent) are outside the oracle.

## Abstractions

* Hashes are collision free and are inputs: `hd`, `dd` and `tkc` are numbers,
  `eid` is the pair `(hd, auth_ref)`.
* The encryption proof `π` is the context it was made for and a validity flag.
* A partial's Chaum-Pedersen proof verifies exactly for a correct partial; `t`
  correct partials open the tag exactly for a good dealing (`dealing_ok`).
* The layout geometry (region outside the frame or over the actor capsules,
  length against the header) is decoded outside the oracle and enters as flags.
* No requirement of this capability keeps a run-level state other than the
  accepted digests; every other check is a pure function.
