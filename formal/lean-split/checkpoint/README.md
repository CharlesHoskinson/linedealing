# split-checkpoint oracle (Lean 4)

`SplitCheckpoint/Spec.lean` is the executable reference semantics of the
OpenSpec capability `split-checkpoint`
(`openspec/changes/add-split-line-dealing/specs/split-checkpoint/spec.md`,
CP-001 to CP-043). The state is one committee node's view together with the
committee contract's landed chain: the landed checkpoints (newest first), the
committee writes, the boot tickets of the last ledger read, the burned index
ranges, the account pools, the sessions, the restart marker of a
whole-committee restart, and the `RestoreDone` statements on the board's
uncovered tail (CP-042).

| Module | Holds |
|---|---|
| `SplitCheckpoint/Spec.lean` | `Params`, `Pool`, `Cp`, `St`, `init`, `Op`, `Obs`, `Refusal`, `landRefusals` (CP-007 to CP-010, CP-040, CP-041), `nextRestartSeq` (CP-011), `movedJump` (CP-041), `pminLowered` (CP-040), the signing checks (CP-012 to CP-015), `floorOf` (the CP-014 floor, DECISIONS 71), `continuous` and `wholeRestart` (CP-017, CP-018), `readLedger` (CP-020 to CP-029), `burnSessions` (CP-022), `genBurn` (CP-021), `reappend` (CP-042), `landNode` (CP-025, CP-027), `reshare` (CP-031, CP-032), `belowFloor` (CP-036), `apply`, `runOps`, `validState`, `stepRefusals`, the theorems |
| `SplitCheckpoint/Tests.lean` | pins from the scenarios (`decide +kernel` and `#guard`), witnesses |
| `SplitCheckpoint/Audit.lean` | `#print axioms` of every theorem and `#audit_ns SplitCheckpoint`, pinned (generated by `../scripts/gen_audit.py`) |
| `Main.lean` | the codec only, through `../codec` |

Build and gates (from `formal/lean-split`, under `heavy-run`):

    (cd checkpoint && lake build --wfail)
    ./gates.sh oracle checkpoint
    ./gates.sh trace checkpoint

## Modes

Default: one `kink-implementation/1` request with `inputs = {"params", "ops"}`
and `params = {"n", "f", "mode", "B", "slot_anchor", "d_rec"}`. Parameters
outside the domain (`f ≥ 1`, `n ≥ 3f + 1`, `B ≥ 1`) give `{"end":
"could-not-apply", "reason": "outside-capability"}`. Otherwise the answer is
`{"end": "final", "cells": {"state", "obs"}}`, the end state of the run from
`init` and one observation per operation. A refused operation is the
observation `{"refused": CODES}` and changes nothing; the run goes on.

`--step`: JSON Lines `{"state", "op"}` to `{"state", "obs"}`; a refused
operation gives `{"refused": CODES}`; a state outside `validState` (parameters
outside the domain, or a chain that lowers `h` or `pending_min` or has a pending gap) gives
`{"refused": ["outside-state-domain"]}`; a line that does not decode gives
`{"error": TEXT}`.

Derived parameters: `w = n − 1 − f`, `t = n − f` and `q = ⌊(n + f + 2) / 2⌋`
(`Params.w`, `Params.t`, `Params.q`); `n = 9`, `f = 2` gives `w = 6`, `t = 7`,
`q = 6`.

Operations (`"op"`), with state: `land` (a candidate checkpoint and the Midnight
height), `boot`, `read_ledger` (verified flag, boot tickets, covered bindings),
`open_session`, `open_account`, `bind_account`, `restore_done`, `lose_tail` (the
board loses its uncovered tail, CP-042), `recover`, `cold_start`, `eks`,
`non_tee_restart`. Queries, no state: `sign_bf`,
`sign_settle`, `sign_pending`, `sign_seat_root`, `order_request`, `covered`,
`release_anchor`, `reshare`, `due`, `may_reboot`. Observations: `ok`,
`refused`, `bool`, `slots` (the reshared slots).

A `RestoreDone` is `{"node_index", "boot_ctr", "cp_seq", "whole_restart"}`
(CP-016); a seat-log binding entry is `{"kind": "bind", "nf", "e"}`, the slot
nullifier and the hidden digest (CP-016, DECISIONS 69 item 1). The state carries
`pending_restores` (the RAM copies) and `board_restores` (the board's uncovered
tail).

An unverified `read_ledger` on a ready node is the CP-043 transition, not a
refusal: the observation is `ok`, every field of the last verified view stays,
and `ready` becomes false until a verified read (ledger 6). On a node that is not
ready it is refused with `ledger_unverified` (CP-019).

| Code | Requirement |
|---|---|
| `below_floor` | CP-036 |
| `h_lowered` | CP-007 |
| `ledger_unverified` | CP-019, CP-043; a not-ready node's session, account, bind and anchored release (ledger 6) |
| `no_restore_statement` | CP-010 |
| `pending_gap` | CP-008 |
| `pending_min_lowered` | CP-040 |
| `recovery_early` | CP-035 |
| `restart_jump` | CP-009, CP-041 |
| `no-rule` | no requirement defines the event (ledger 2, 3, 5, 7, 8, 9) |
| `outside-capability` | parameters outside the domain; tickets or a `RestoreDone` naming a seat `≥ n`, or a seat twice |
| `outside-state-domain` | a `--step` state outside `validState` |

The hyphenated codes are harness codes; the spec names none of them. Several
landing checks that fail together return every code, sorted by code string
(ledger 1): `h_lowered`, `no-rule`, `no_restore_statement`, `pending_gap`,
`pending_min_lowered`, `restart_jump`. `pending_min_lowered` sorts after
`pending_gap` and before `recovery_early` in the code enum.

## Claims

| Claim | Theorem | Statement |
|---|---|---|
| C16 (CP-020, CP-023, CP-038) | `C16_run_window_burned` | in every run from `init`, when the node then reads a whole-committee restart without slot anchors, every index that could pass the signing window of the latest landed checkpoint (`h < ℓ ≤ h + B`, or `pending_min ≤ ℓ ≤ h`) is burned and stays burned over any later operations |
| C16 (CP-020) | `C16_restart_burns_range` | after such a read, every index of `[pending_min, h + B]` of each pool of the checkpoint read is burned |
| C16 (CP-021, CP-038) | `C16_acct_burned` | after the first such read of a restart generation no account slot is `free` or `bound` |
| C16 (CP-024, CP-038) | `C16_session_burned` | a session opened while the restart is open holds every burned index of its pool |
| C16 (CP-039) | `C16_bounded_loss` | the burn range of one pool of one checkpoint read holds at most `B` usable indices plus its pending indices |
| C16 (CP-039, CP-041) | `cp041_jump` | with slot anchors off, a checkpoint that lands and moves `restart_seq` has `h ≥ cp1.h + B` and `pending_min > cp1.h + B` for each pool of both: each syncing seat retires one window (ledger 17) |
| C16 (CP-022) | `cp022_sessions_burned` | a whole-restart read without slot anchors puts every index of `[pending_min, h + B]` of the checkpoint read into each open session of that pool |
| contract (CP-007, CP-008, CP-040) | `cp007_cp008_run_chainOk`, `cp040_run_pmin` | in every run from `init` the landed chain never lowers `h` or `pending_min` and no landed pool has a pending gap |
| signer (CP-014, CP-040; DECISIONS 71) | `cp014_pmin_floor`, `cp014_cp040_floor_kept` | on a landed chain, pool fields that `sign_pending` accepts, with `h` not below the landed `h`, never have `pending_min` below the landed `pending_min`, so CP-040 never refuses an honest checkpoint (finding F7) |
| node (CP-042) | `cp042_reappend` | after a verified read every statement held in RAM is on the board |
| node (CP-043) | `cp043_keep_view`, `cp043_not_ready` | an unverified later view changes only `ready`; a node that is not ready binds nothing and refuses an anchored release |

These are the state parts of C16. The key parts of CP-038 (every key opens from
tier 0 on `t` nodes or from `E`) and its coin part are outside the oracle: the
state holds no key material and no coins. That a slot collects no honest
partials for two tickets is the burn: a burned index is never signed again.

## Abstractions

* Roots and digests are numbers; a Merkle root is the list it commits to
  (`settle_root`, `bf_root`, `seat_roots`).
* Signing checks (CP-012 to CP-015) are pure functions of the candidate and
  the node's own view, given as inputs.
* The node and the committee contract share one state: the contract's landed
  chain and the node's reads of it.
* Midnight heights are inputs of `land` and `recover`; board heights are fields
  of the checkpoint and inputs of `order_request`.
* The checkpoint byte layout and payload size are not modeled (ledger 13), nor
  the 117-byte `RestoreDone` encoding (DECISIONS 69 item 8).
* A session seal is not modeled; a session's burn list is its RAM view (ledger 16).
