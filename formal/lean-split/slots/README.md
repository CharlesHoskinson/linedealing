# split-slots oracle (Lean 4)

`SplitSlots/Spec.lean` is the executable reference semantics of the OpenSpec
capability `split-slots`
(`openspec/changes/add-split-line-dealing/specs/split-slots/spec.md`, SL-001
to SL-030). The state is the slot ledger as one committee node sees it: the
committee pools `(suite, epoch)`, the ECDSA account pools, the slot shares of
the node's seat, the requests whose authorization is in force, and the
requests that opened, lapsed or ended.

| Module | Holds |
|---|---|
| `SplitSlots/Spec.lean` | `St`, `init`, `Op`, `Obs`, `Refusal`, `cstep` and `cnew` (committee slots: SL-001, SL-004, SL-005, SL-008 to SL-010, SL-022), `estep` and `enew` (ECDSA slots: SL-003, SL-006 to SL-009, SL-011), `sstep` and `snew` (seat slots: SL-018 to SL-021, SL-030), `verdict` (SL-012 to SL-015), `batchCheck` (SL-023, SL-024), `qualified` (SL-025), `anchorOk` (SL-026), `opRefusals`, `apply`, `runOps`, `validState`, `stepRefusals`, the theorems |
| `SplitSlots/Tests.lean` | pins from the scenarios (`decide +kernel` and `#guard`), witnesses |
| `SplitSlots/Audit.lean` | `#print axioms` of every theorem and `#audit_ns SplitSlots`, pinned (generated by `../scripts/gen_audit.py`) |
| `Main.lean` | the codec only, through `../codec` |

Build and gates (from `formal/lean-split`, under `heavy-run`):

    (cd slots && lake build --wfail)
    ./gates.sh oracle slots
    ./gates.sh trace slots

## Modes

Default: one `kink-implementation/1` request with `inputs = {"params": {"mode",
"w"}, "ops"}`. The answer is `{"end": "final", "cells": {"state", "obs"}}` with
one observation per operation. A refused operation is the observation
`{"refused": CODES}` and changes nothing; the run goes on.

`--step`: JSON Lines `{"state", "op"}` to `{"state", "obs"}`; a refused
operation gives `{"refused": CODES}`; a state outside `validState` gives
`{"refused": ["outside-state-domain"]}`; a line that does not decode gives
`{"error": TEXT}`.

Operations (`"op"`): `deal_c` and `deal_e` (deal `k` slots into a pool),
`open_c` and `open_e` (a header opens at a board position and names slots),
`in_force` (an authorization comes into force with the root its source opens),
`lapse`, `reserve` (`q` votes with one header hash commit), `claim` (ADMITTED),
`end` (FINAL, VOID or EXPIRED), `burn_range` and `burn_pool` (the
whole-committee restart burns of CP-020 and CP-021), `seat_put`, `seat_bind`,
`seat_release` and `seat_burn` (the seat slots, TEE only), and four checks that
keep no state: `judge` (the window verdict on each committee index of a
header), `batch` (the batch equation of a dealer message), `qualify` (the
qualified dealers of a slot) and `anchor_gate` (the `slot_anchor` release
gate). Observations: `ok`, `refused`, `void` (`SLOT_TAKEN`, SL-016),
`released` (a partial for digest `d`), `verdicts` (`in_window`, `SLOT_TAKEN`,
`above_window`, `pool_unlisted`), `complaint` (the failing polynomials, empty
when the batch holds), `qualified` (the dealers, or `null` while fewer than
`t` exist) and `gate`.

## Refusals

| Code | Requirement |
|---|---|
| `slot_bound` | SL-020 |
| `no-rule` | no requirement defines the event, or a prohibition has no code (ledger 1, 4 to 8) |
| `outside-capability` | a value outside a domain sentence (ledger 9) |
| `outside-state-domain` | a `--step` state outside `validState` |

`above_window` and `pool_unlisted` (SL-014, SL-015) are votes that the node
refuses to cast on a header. They are verdicts of `judge`, not refused
operations. The hyphenated codes are harness codes; the spec names none of
them.

## Interpretation

| ID | Trigger | Guard | Response | Unchanged |
|---|---|---|---|---|
| SL-001, SL-022 | `deal_c` | none | `k` new UNNAMED slots of pool `(suite, epoch)` above its highest index | other pools |
| SL-003, SL-022 | `deal_e` | none | `k` new UNNAMED slots of account pool `p` above its highest index, with `leaf_set` and `root` | other pools |
| SL-004 | `open_c` | slot `prec = none` and `bstat = UNNAMED` | record the namer; `prec` := the namer with the lowest board position; NAMED | a slot under a precedence keeps it |
| SL-016 | `open_c`, `in_force` | the authorization of the opened request is in force (DECISIONS 68), and a slot that its header names has `prec` another request; read at the open of a request in force and at the `in_force` of an opened request | `void` (SLOT_TAKEN) | the slot's `prec` and `bstat` |
| SL-006, SL-007 | `open_e` | the namer is in force under the slot's root | record the namer; a slot with `prec = none`, not BURNED, gets the earliest namer in force and moves to NAMED (ledger 2, 3) | a slot named without an authorization in force (only the namer is recorded) |
| SL-016 | `open_e`, `in_force` | the authorization of the opened request is in force (DECISIONS 68), and a named ECDSA slot's `prec` is another request in force | `void` (SLOT_TAKEN) | the slot's `prec` and `bstat` |
| SL-006 | `in_force` | the request is not in force, lapsed or ended | each ECDSA slot it named, under its root, with `prec = none` and not BURNED, gets the earliest namer in force | committee slots |
| SL-005, SL-010 | `lapse` | the request is not in force, lapsed or ended | each committee slot where it holds `prec` is BURNED | ECDSA slots |
| SL-005, SL-010 | `open_c` of a lapsed request | the slot gets `prec` of the lapsed request | the slot is BURNED at once (`burnIfLapsed`, ledger 10) | the other slots |
| SL-008 | `reserve` | the request is in force and not ended | NAMED slots where it holds `prec` become RESERVED; on ECDSA slots `reserver` := the request | other slots |
| SL-009 | `claim` | the request is not ended | its RESERVED slots (committee by `prec`, ECDSA by `reserver`) become CLAIMED | other slots |
| SL-010, SL-011 | `end` | the request is not ended | committee slots where it holds `prec` and ECDSA slots where it is `reserver` are BURNED | ECDSA slots where it holds only `prec` (SL-028) |
| SL-018, SL-019 | `seat_bind` | TEE; slot `free`, or `bound` to the same `d` | `bound(d)`; current once the `slot` entries and the sealed version each have `w` acks | other seat slots |
| SL-019, SL-021 | `seat_release` | TEE; slot `bound(d)` and current | `released d`; `d` recorded as signed | other seat slots |
| SL-020 | `seat_release` | slot `bound(d')` with `d' ≠ d` | `slot_bound` | state |
| SL-018, SL-030 | `seat_burn` | TEE; slot not burned | `burned` | other seat slots |
| SL-012 to SL-015 | `judge` | `B ≥ 1` | per index: `pool_unlisted`; else `above_window` for `ℓ > h + B`; else `in_window` for `h < ℓ`, or for a pending index of the request at or above `pending_min`; else `SLOT_TAKEN` | state |
| SL-023, SL-024 | `batch` | none | the failing polynomials (from 1) | state |
| SL-025 | `qualify` | `t ≥ 1` | the first `t` dealers without a valid complaint, in board order | state |
| SL-026 | `anchor_gate` | none | true when `slot_anchor` is off, or when `nf → d` is covered and no covered entry binds `nf` to another digest | state |

## Requirements

The Sentence column is the spec sentence, word for word (`|` escaped).
`../scripts/req_table.py` writes this table from the spec and the Lean
declarations that name each ID, and `gates.sh trace slots` fails when it
differs. `proved` comes from `trace.json`, read against each theorem
statement. When a theorem states only part of a requirement, the Lean name
column lists it and the row stays `defined`: SL-006 and SL-008
(`C13_ecdsa_prec_in_force` states that `prec` and `reserver` are in force, not
which request is chosen), SL-025 (`sl025_no_complained` states `t` dealers
without a complaint, not that they are the first `t`), SL-026
(`sl026_one_ticket` states one ticket per nullifier, not the coverage) and
SL-027 (`C12_run_one_ticket` is the per-node seat part).

## Claims

| Claim | Theorem | Statement |
|---|---|---|
| C12 (SL-021, SL-027) | `C12_run_one_ticket` | in every run from `init`, each seat slot holds partials for at most one ticket digest |
| C13 (SL-005, SL-010) | `C13_run_lapsed_burned` | in every run from `init`, every committee slot whose `prec` is a request with a lapsed precedence is BURNED, also when its header opened after the lapse |
| C13 (SL-028) | `C13_ecdsa_burn_only_if_reserved` | one operation sets `bstat = BURNED` on an ECDSA slot only as the end of the request in its `reserver`, or as the restart burn of its pool |
| C13, C6 part (SL-006, SL-008) | `C13_ecdsa_prec_in_force` | in every run from `init`, the `prec` and `reserver` of every ECDSA slot are requests with an authorization in force under the slot's root, so a copied header without an authorization holds no ECDSA slot |

These are the state parts of the claims at one node. The cross-node part of
C12 (no two nodes sign one slot for two tickets, rollback within the bound of
DESIGN §7.7, the restart burn) needs split-checkpoint and is outside this
oracle (ledger 7).

## Abstractions

* Requests, tickets, nullifiers and dealers are numbers; the ticket digest
  `H(tk)` is a number `d`.
* The window check reads the latest landed checkpoint of a pool as inputs
  (`listed`, `h`, `pending_min`, the pending list), and `B` is an input; the
  oracle keeps no checkpoint state.
* The batch equation is the list of polynomial verdicts. The random linear
  combination with 128-bit coefficients drawn after the message (SL-023)
  rejects a bad batch with overwhelming probability, and the oracle takes it
  as exact.
* A complaint is valid or not as an input flag; a seat-log coverage is the
  list of covered `(nf, d)` entries.
* A lapse is an input event; the oracle does not compute `b + Δ_c`. The lapse
  holds from then on: a precedence that a lapsed request takes later burns.
