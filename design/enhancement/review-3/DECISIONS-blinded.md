# Lead decisions for the merge

Inputs: three independent protocol proposals (A, B, C) and three hardening notes.

Each decision names the proposals it follows and the reason.

## Protocol

1. **Key split.** Schnorr and Ed25519: additive `X = X_u + X_f + tw·G` (all three proposals). ECDSA: additive `x = x_u + x_f + tw` with a pool of one-use presignature slots prepared in an interactive session at address creation (proposal A, proposal B). Reason: two proposals agree, it keeps one key algebra for all suites, and the brief allows one-time setup interaction. proposal C's multiplicative split `x_u·(X_f + δG)` is recorded as the alternative. The committee side of slot generation at `t = n − f` (threshold multiplication) is an open item with named candidates.
2. **Committee half.** One root key `x_f` per curve from one DKG, Shamir at `t = n − f`. Each address uses a secret per-address tweak; the tweak reaches the committee only inside the sealed request (proposal B, proposal C). Reason: no per-address DKG, rotation reshares O(1) secrets, and addresses do not link on chain. proposal A's per-address DKG is rejected for its cost.
3. **The owner's one move.** The owner deals sealed user half-signatures, one per variant of a fee grid that spends one pinned input or nonce (all three proposals). The committee adds its half. Sealed mode's guarantee carries over: all n nodes corrupt cannot sign outside the dealt variants, and never learn `x_u`.
4. **Reading of R1.** No spend unless one of the charter's three sources authorizes it, the authorization settles on Midnight, and the source contributes its own key element. The committee holds no source's element (proposal C's reading, with proposal B's destination pinning). Seizure goes only to the charter sink `D_reg`, exit only to the standing exit record `D_exit`.
5. **Seizure.** For charters with `seizable = true`, the user's half is escrowed at address creation to an independent guardian set G (3 of 5, disjoint from Fenrir operators). G produces a user half-signature only for a settled Midnight seizure, paid to `D_reg` (proposal A, proposal C). Regulated tokens also use asset-level controls (ERC-3643 forced transfer and freeze, Token-2022 permanent delegate and freeze authority) (proposal B). proposal B's vault contracts for native coins are rejected as the default: they break the native single-key output. They stay an option for a charter that demands on-chain seizure of native coins.
6. **Recovery when Fenrir disappears.** The universal path is an independent recovery group E (3 of 5, disjoint from G and Fenrir) that holds a verifiable backup sharing of `x_f` plus the unused committee slot state, and reprovisions a successor committee after a charter-defined Midnight delay (proposal A). A Bitcoin Taproot exit leaf `<T_exit> OP_CSV <K_exit>` is a charter option for unregulated assets (proposal B, proposal C). State plainly that a matured exit leaf ends the hold for that coin.
7. **Blindness on the board.** The request travels as a fixed-size padded envelope. Its data key is dealt by the owner as a Feldman-committed `t`-of-`n` sharing to the nodes' dealing keys `PK_i`, using SCHEME's existing encryption and public complaint, and shares move only after the quorum certificate fixes order (proposal C). The same object serves TEE and non-TEE mode. proposal B's committee BLS12-381 threshold IBE key and proposal A's outer threshold ciphertext are rejected: each adds a DKG and an assumption that the dealer-based envelope does not need.
8. **Covenant enforcement.** Midnight's authorize circuit proves the charter predicate with a private source tag and checks the hold accumulator. Nodes verify the settled authorization before they release a share. TEE mode: the enclave enforces it even if every operator is malicious, while the TEE holds. Non-TEE mode: holds and vetoes are honest-threshold; `t` corrupt nodes can release a user's already-dealt variants despite a later hold. Say so (proposal A).
9. **Blind signing in non-TEE mode.** Nodes sign address-free tickets and verify a hash-only STARK (one BLS12-381 wrap, under 2^21 rows) that each ticket is the sighash challenge of an admitted transaction (proposal C). In TEE mode v1 the enclave recomputes the sighash; the proof replaces it later behind the same interface.
10. **Requirement grading.** Grade honestly per mode, as proposal A and proposal C do. proposal B's all-MET table is rejected. B5 (unlinkability against the host chain graph) is PARTIAL at best with native outputs.

## Veritee hardening

11. **Close the attestation oracle first.** Evidence carries a class byte; caller-chosen payloads get only the public class; internal classes are served on a Unix socket; TPM quotes carry qualifying data (all three proposals).
12. **Verification without MAA.** Committee peers verify raw SNP and HCL evidence in the guest. MAA and the Warden are not in the signing trust base (proposal B, proposal C).
13. **Sealed storage.** `/mnt/persist` becomes dm-crypt with dm-integrity under a vTPM key sealed to PCR 4, PCR 15 (post-setup) and a new PCR 14 for the committee role. Secrets inside use `K_seal = HKDF(K_tpm ‖ K_grp ‖ ratchet)`, where `K_grp` is a peer-released threshold PRF output that peers release only to a boot holding the current Midnight boot ticket (proposal C, proposal B). Nonces and presignature state never reach disk. SNP-derived keys are rejected: the Azure paravisor hides `MSG_KEY_REQ` and binds it to the paravisor, not the image.
14. **Rollback and clones.** Every boot needs a Midnight boot ticket with counter + 1, which fences clones and superseded instances (all three). Before a PREVOTE, a partial signature, a decryption share or a sealed release leaves a node, `q = 6` peer enclaves witness `(node, rid, g) → digest` and refuse a second digest (proposal C, proposal B). Midnight checkpoints of board state set the replay floor. Midnight finality before every output (proposal A) is a high-value profile, not the default.
15. **Offline encryption to the committee.** Each node generates its static epoch keys in the guest (X25519 HPKE key, SCHEME dealing key `PK_i`, board post key) under a reserved evidence class. Peers verify them and the epoch key set is recorded on Midnight. A wallet reads one record and encrypts once (all three).
16. **Secret release.** Committee secrets exist only through DKG, reshare and peer repair between attested enclaves. TLS keys are generated in the guest (ACME TLS-ALPN-01 or the internal CA). Operator inputs arrive only sealed to an attested provisioning key. Key Vault and managed identity are removed from committee images. Azure Secure Key Release is rejected as the gate, because the operator controls its policy and identity (proposal C, proposal B; proposal A's broker becomes the peer quorum).
17. **Erasure.** zeroize, mlock, no swap, no core dumps, `PR_SET_DUMPABLE=0`, and key destruction by ratchet and per-epoch group secret (all three).
18. **Whole-committee cold start.** Must be specified: what survives if all nine nodes reboot at once. Take the proposals' answer if one exists; otherwise define a cold-start path through the recovery group E and Midnight checkpoints.

## Requirement: seizure is optional

Requirement: "We have to have the ability to use fenrir with or without this mode." Seizure, freeze, blacklist, reversal and legal holds are a per-charter option, never a property of the protocol. 

19. **Charter custody profiles.** Every address carries a profile fixed at birth in its charter:
   - `P0 existing`: the original line dealing on an existing owner address. No Fenrir co-custody, no holds, no seizure (book level L0).
   - `P1 co-custody`: split-line dealing, user half plus Fenrir half. Covenant predicates and approver vetoes the owner chose apply; no seizure, no third-party freeze, no guardian escrow. Exit to the standing exit record is unconditional when Fenrir disappears (recovery group or exit leaf).
   - `P2 regulated`: P1 plus the charter's seize, freeze, blacklist and hold entries, the guardian escrow G and the hold accumulator; exit is subordinate to a live hold.
   The protocol, envelope and committee state machine are identical across profiles; P2 only adds authorization sources and checks. Nothing in P0 or P1 depends on G, `D_reg` or the hold accumulator, and no P2 component is needed to run Fenrir.
20. R1 is read per profile: P0 and P1, no spend without the owner's own authorization (the owner's half-signature); P2, no spend without one of the charter's admitted sources.

## Requirement: n shards, arbitrary actors

Requirement: "Allow for a split into n shards so we can have arbitrary actors involved in the production of a transaction. Fenrir does the MPC and the outside parties provide the shard."

21. **Multi-shard split.** An address key is `x = x_f + tw + Σ_{j∈A} x_j` over a set `A` of outside shard holders (the user, an issuer, a custodian, an approver, a guardian group, a regulator, any party the charter names). Fenrir holds only `x_f` and runs the MPC. Each outside actor holds its shard and contributes one sealed half-signature per variant, offline, with one move. The user half of P1 is the case `|A| = 1`.
22. **Access structure in the charter.** The charter fixes, at birth, a monotone access structure over the shards, always ANDed with Fenrir. Building blocks: AND of shards (additive), threshold `k`-of-`m` among a group of actors (the group's shard is Shamir-shared among its members, and each member's contribution is weighted by its Lagrange coefficient for the chosen subset), OR (escrow of one shard to another holder, as the P2 guardian escrow). P2's seizure path is `Fenrir AND (user OR G)` with `G` a 3-of-5 group.
23. **Fixing the signer set before the challenge.** For Schnorr and Ed25519 the challenge depends on the aggregate nonce, so the contributing subset and every contributor's nonce must be fixed before anyone computes a half-signature. Each actor publishes a pool of two-nonce commitments `(D_j, E_j)` on the board (as the committee does). The initiator's envelope names the subset, the actors' slots and the fee grid; FROST-style binding factors `ρ_j = H(j, message, all commitments)` fix `R`. Each named actor reads the request (actors are parties and may see what they co-sign; blindness is toward Fenrir operators) and posts its sealed contribution before expiry. If an actor fails to respond, the initiator issues a new generation with another subset. An actor never uses one slot for two messages; its software keeps that state.
24. **ECDSA with many actors.** The multiplicative structure needs a joint presignature session among Fenrir and every actor of the access structure at birth (or per slot refill). State its cost and the open instantiation.
25. **Blindness.** Envelope contents are hidden from Fenrir operators exactly as before. Each actor sees the request it co-signs. Actor identities are hidden from operators where the access structure allows it (contributions are sealed capsules inside the envelope).

## Speed

All three proposals find the same bottleneck: the committee's Schnorr slot pool, about 110 ms per node per K = 8, L = 2 spend unbatched, against about 12 ms on the request path. Latency is five serial board commits after Midnight finality.

26. **Arithmetic (all three, no new proof).** Evaluate Feldman commitments by Horner with the node index as a small integer (addition chains), use the fixed-base generator table, check torsion once per decoded point and hash wire bytes instead of re-encoding, reduce 512-bit hashes in one wide reduction, batch affine conversions with one inversion, verify batches by a random linear combination with 128-bit coefficients and a per-polynomial fallback that names the bad dealing, and run the combiner optimistically (check partials only when the combined signature fails). The prototype defects at `impl/src/algebra.rs:140-147`, `impl/src/algebra.rs:10`, `impl/src/ed25519.rs:37-53,423-430,512,589` and `impl/src/signing.rs:78-81,160` are fixed in the discovery prototype (PLAN item 13).
27. **Slot pool.** Per-node slot commitments are evaluated lazily and cached; a dealer's batch of slot dealings is checked with one equation (proposal B, proposal A, proposal C). A committee slot serves one (generation, input) pair, not one variant (proposal C): the committee releases one partial per slot, for the one variant that is broadcast, so `K` variants on one slot never yield two committee partials. `G_max = 2` generations per request is a protocol constant; a second fee bump is a new request. C12's counting is restated around the anchor (proof obligation). ECDSA keeps `K·L` slots: two user halves on one ECDSA slot reveal the user's slot secrets.
28. **One polynomial per envelope (proposal C).** The data key `κ_0` stays the only dealt secret. Header and variant keys are threshold-PRF outputs `κ_0·H_c(dd ‖ label)` (the construction already used in §7.4). The 16 inner dealings go; an outside actor deals nothing. Theorem D is restated and C8, C9 rest on DDH (proof obligation). Reason: it removes 40% of request-path CPU and lets `n = 17` keep the full fee grid in 16 KiB.
29. **Latency.** The wallet posts the envelope while `authorize` finalizes (all three); nodes release only after both the QC and finality. ACK merges with share release, and OPENED with ADMIT and OBS, which needs the SCHEME §3.6 rule change "OBS is posted with ADMIT" (proposal C, proposal B); the normal path is two board commits after finality. The TEE peer witness rides on board votes with one group-committed flush per block (proposal B). Board-first authorization (no Midnight wait) is an option for P0 and for P1 charters with stateless predicates only; it is forbidden for P2 and for cumulative limits or vetoes (proposal C).
30. **Ticket proof: reverses item 9 (proposal C, proposal B; proposal A dissents).** The ticket commits `x(R)`, so the proof contains no curve arithmetic. One midnight-zk PLONK circuit at `k = 18` proves the sighash relation with the library's own SHA-256, SHA-512 and Keccak gadgets, sharing sighash prefixes and midstates. No STARK and no BLS12-381 wrap. Reason: midnight-zk has no STARK verifier gadget, the wrap (2^20) is larger than the statement it wraps (2^18), and the single circuit fits the k ≤ 21 rule with room. proposal A's alternative (KoalaBear STARK, aggregation, one wrap) stays the fallback if Compact cannot call the hash gadgets; that is new open item O25. Poseidon2 is used only for protocol-internal hashes; host-chain sighashes stay SHA-256, SHA-512 or Keccak.
31. **Quorum certificate.** Batched Ed25519 signatures, not BLS aggregation (proposal C over proposal B): a pairing check costs about 1.3 ms, twelve Ed25519 verifications about 0.4 ms, less batched. Aggregation pays at hundreds of signers.
32. **Deferred, each needs a proof first:** proposal B's seeded shares (`f + 1` ciphertexts, shares of `t − 1` nodes defined as the pads) and proposal C's derived slot shares, because both touch the public complaint and Theorem E's related-dealing defence; Vandermonde extraction of slots waits on O6.

**Rejected (union of the proposals' "what not to do"):** one user or actor nonce across variants (breaks C3); shared ECDSA slots (C3); returning named but unused slots to the pool (C12); one committee nonce per slot (ROS); any share or partial before the QC (C8); release at Midnight inclusion before finality (C6); board-first for P2 or stateful predicates (C7); skipping the witness on an optimistic path (rollback); short batch coefficients or no fallback; variable-time arithmetic on secrets (TEE timing); replicated PRSS for nonces (no commitments, C(n, t−1) keys); an anchor output for fee bumps (B5); a second frame class (O7); GPUs on nodes.

**Cost after 26–31 (estimates, to be measured under `heavy-slot --exclusive` in `impl/benches`, PLAN item 13):** request-path CPU 1.8–2.7 ms per node; slot replenishment 1.2–3.6 ms per spend; one core serves about 160–400 requests per second at `n = 9` and 95–260 at `n = 17` (proposal C's calibrated range; proposal B's 730 and 395 assume EPYC and every batch win). Latency `F_M` + about 2 board commits.

## Folding 26–32 into DESIGN.md: conflicts with the multi-shard text

Items 26–32 were written for the single-user form. Each entry below resolves a point where they meet the multi-shard design (items 21–25) or leave a rule unstated. Every resolution keeps the security claim of DESIGN.md §9 that was at stake.

33. **Actor capsules carry the header key and the capsule keys, never `κ_0`.** Item 28 makes every key a PRF output of `κ_0`. An actor that held `κ_0`, as the multi-shard actor capsule did, would derive every variant body key and read the initiator's scalars and the other actors' contributions for unselected variants, which breaks C9 and the secrecy part of C18. The capsule now holds `k_hdr`, the position, the token and the `K` random capsule keys `ck_v`. Its size is unchanged (`97 + 32·K`).
34. **"An outside actor deals nothing" means no contribution dealing.** An actor seals its scalars to the variant keys `P_{v,g} = y_{v,g}·G` in the header (proposal C §3.7(a)). A contribution frame still carries the one outer dealing every envelope has, because a frame without a dealing and its proof `π` is distinguishable before ordering, which breaks C21 and the B5 grade of item 25. An embedded contribution has no frame and no dealing. Cost of the choice: about 0.8 ms per node per contribution frame, against 0.06 ms for an embedded one.
35. **A collecting request keeps a separate OPENED vote.** Item 29 merges OPENED with ADMIT. A request with empty actor slots cannot be admitted in the vote that opens it, and it must hold its slots before its actors answer (C20). Its nodes vote OPENED once the authorization is in force, which reserves the slots; ADMIT with OBS follows collection. The two-commit path applies to requests with no collection: the single-user form and requests whose contributions are all embedded. Slots are reserved by the first `q` votes with one header hash while the authorization is in force, and named slots that no request reserved stay in the pool.
36. **An actor burns one pool pair per half, not per `(variant, input)`.** Item 27 puts several variants on one committee slot, and the Rejected list forbids one actor nonce across variants. A named actor therefore uses `H = L·Σ_v min(v, G_max)` pairs per request, 30 at `K = 8`, `L = 2` (was 16). `N_pool = 64` stays; an actor refills below `H` unused pairs. ECDSA keeps `K·L` halves.
37. **Contributions are checked at release, in both modes.** With scalars sealed to `P_{v,g}` no node can check a contribution before its variant is released, so the TEE-mode check before ADMIT is gone and a bad contribution costs a reissue in either mode. O21 is widened from non-TEE mode to both. The header carries no contribution points `S = s·G`: the combiner checks each scalar against its equation directly, and only when the combined signature fails. This departs from proposal C §3.2, which kept the points; they served no check once every check runs on the opened scalar, and they cost 1 KB of frame.
38. **The release witness is sent after the anchor, not on the ADMIT vote.** Item 29 puts the TEE witness on board votes. The digest of a release entry is `(j_g, H(tickets))`, and `j_1` is fixed only by the OBS reports of the committed ADMIT block, so a node cannot attach that entry to its own ADMIT vote. `open` entries ride on the vote for the ordering block; `release` and `slot` entries go in one batched message per peer and board height right after the anchor; peers flush once per height in both cases. The entry digests are unchanged, so the bound of §7.7 needs no new proof. proposal C's merge of the open and release witness is not taken: it changes the digest and needs a proof.
39. **Two rules of the proposal mechanisms that the cost figure of items 26–31 assumes are now stated in the design.** Lazy checks: a check that concerns one variant runs when that variant is released, and the comparison of the ticket's `x(R)` with the node's own `R` is a precondition of release (proposal C §3.5). Board votes: a node signs once per block, the vote lists its posts, complaints and VOID posts stay individually signed, and peer-channel messages carry no signature (proposal C §3.6). Not taken from the proposals, because no item adopts them: the single binding factor for actors (it changes O6 and O20), ristretto255 for suite 3, and the ECDSA birth changes.
40. **C18's secrecy needs an honest initiator.** An actor cannot check that `P_{v,g}` is the PRF key of its label without `κ_0`. A dishonest initiator that substitutes its own key reads its actors' scalars. It gains no signature, the adversary of C17 holds those scalars in any case, and the combiner's check `y_{v,g}·G = P_{v,g}` ends the request VOID. The limit is stated in §6.4 and C18.
41. **Status changes in §9, and new open items.** C8 goes from proved to sketched and C9, C18 secrecy from information-theoretic to computational (O26, Theorem D restated). C12 goes from proved by counting to sketched (O27). C13's merged step is O28. C6 and C11 for board-first are O29. O25 is the Compact access to the hash gadgets, with the STARK path as fallback. O30 holds the deferred items of 32. O31 is the measurement of §11. O4, O6, O16, O18, O20 and O21 are restated.
