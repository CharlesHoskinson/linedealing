## Finding raised during the merge

Grafting an identity of the form `H(chain, board, X, owner_nonce)` onto sealed mode opens a squat. The base's sealed-mode proof showed knowledge of `e` only, so anyone could bind any identity. A proof of knowledge of the first sealed signature closes that until a signature is released; after release the signature is public and can be wrapped in a new message that claims another pending request's `owner_nonce`. **Fixed, §3.2:** `π` proves knowledge of `x` (open) or of `s_{1,1}` (sealed), and the sealed `rid` is tied to `hd`. This is a deliberate deviation from the single identity formula named in the merge brief. Checks D9, D15.

## Non-blocking findings

Fixed: Ethereum `yParity` after low-s (§3.7, D4). `G` counts total generations (§3.2, §6.1). Costs include `π`, `F_0`, PREVOTE and post-signature verification and open Schnorr (§7). `F_OMS` lets a qualified sealed coalition release after close (§6.1). `R = O` and `s = 0` kill a generation (§3.8). Slot consumption is durable (§3.9). Safety does not depend on timing (§2). Repeated `R` inside one message is rejected (§3.4 check 7).

Listed, not fixed: the two-nonce Schnorr proof (PROOFS.md Theorem B) is not compared with the published proofs; the changes of the proofs revision (rows C19 to C23) have had no outside review; delivery is proved by ACK quorum and not by the message (gap 1); a signed Bitcoin transaction outlives the window; an `ALL` sweep on an EIP-1559 chain leaves a remainder; epoch keys compromised before erasure open old dealings; request-channel spam needs a posting fee; no adaptive security; resharing volume at `n = 256`.

- **D1 pad reuse.** Inputs: `k = sc("nonce-1")`, `R = kG`, `w = 1/k`, `μ = x/k`, `h = TH("test/msg", "tx-A") mod q`, `s = h·w + r·μ`. Procedure: encrypt `w_i`, `μ_i` for all `i`; take `δ_i = ct_μ,i − ct_w,i` for `i = 1..6`, interpolate `δ` at 0, compute `w' = (s − rδ)/(h + r)`, `x' = 1 + δ/w'`. Expected: with one pad per slot, `x' = x`; with the slot labels of §3.1 (`02 02…` and `02 03…`), `x' ≠ x` and `x'G ≠ X`. Result: both as expected.

(b) Two-nonce Schnorr, slot 1, digests A, B, C: solve the 3×3 system `s = σ·d + σρ·e' + c·x`. Expected: `x` recovered from three signatures. (b2) With only digests A and B, the wrong key `x + 1` has a consistent `(d, e')`, so two signatures do not determine `x`. (c) One-nonce Schnorr: two signatures give `x`. Result: all hold. These are the events that vote rule 1 and the slot ledger exclude; for ECDSA one repeat is fatal, for two-nonce Schnorr two repeats are.
- **D8 open BIP340.** Inputs: slots 1..8 with `d = sc("d/slot")`, `e' = sc("e/slot")`, digest `dg = TH("LD1/dg", m)`, `ρ` from `LD1/bind`. Expected: every partial passes `s_i·G = σ(D_i + ρE'_i) + c·X_i`; the combined `(x(σR), s)` passes BIP340 verification; both parities of `R` occur (4 even, 4 odd). Result: holds.
- **D9 identity.** Expected: the open `rid` changes with `owner_nonce` and has no input from `ct` or `π`; the sealed `rid` differs for two dealings under one `owner_nonce`. Result: holds.
- **D10 quorum intersection.** Expected: `2(2f + 1) − n = f + 1` for `n = 16, 64, 256`. Result: holds.
- **D11 anchor.** (a) Honest reports `[100]×5, [101]×5, [102]×1`, `f = 5`. Expected: no height has 6 posts (the old rule is undefined); entry 6 by height is 101. (b) Five Byzantine reports of `10⁹`, or of 0, added to six honest reports: the anchor stays an honest value. (c) One Byzantine post `(101, bogus hash)` placed at entry 6: under a rule that takes the hash from the post, all eleven honest nodes reject and the attempt fails; under the height-only rule of §3.6 the anchor is each node's own block at 101 and no honest node rejects. Result: holds.
- **D12 fee bump.** Inputs: `vsize = 141`, market rate 10 at both anchors, increment 1, ceiling 3,000. Expected: a rebuild without the prior transaction pays 1,410 again, below the required 1,551; the §4 rule pays 1,551. Type-2: prior `maxFeePerGas = 62`, `tip = 2`, flat base fee; expected new values 70 and 3, each at least 10% higher. Result: holds.
- **D13 fee ceiling.** Inputs: input 10,762, payment 10,000, two-output fee 562, dust 294, ceiling 700. Expected: change 200 is dust; without it the real fee is 762 > 700; `Build` returns ⊥. Result: holds.
- **D14 resharing.** Inputs: dealers `Q = {1, 2, 4, 6, 9, 12}` reshare `w` and `μ` of D1 with `t' = 6`. Expected: each dealer's constant term equals `Eval` of the old commitments; the new constant commitments are `G` and `X` in base `R`; partials from new shares of nodes `{3, 5, 8, 10, 14, 16}` interpolate to the same valid `s`. (b) Counting: `(2f + 1) + (f + 1) − n ≤ f`, so a lock quorum and a resharing set can overlap in Byzantine nodes only, which is why §5 relies on board order. Result: holds.
- **D15 authorship proof.** Inputs: sealed point of D3, `a = sc("pok-a")`. Expected: `z·R = T + c·F_0` for `z = a + c·s`; fails for another `s`. Result: holds.

Not yet scripted: the board state machine (no tombstone from a transient condition; no generation both in flight and reshared; the board cut), Ed25519 suite arithmetic, HASH160 and Keccak address checks, real sighash encodings. These belong to experiment steps 1 and 4.

## Dissent preserved

- **review-fable: cand-5d08 as the base, with ECDSA added only as Trout++ Protocol 5 verbatim.** Not adopted. Two of three head-to-heads chose line dealing, and its ECDSA path needs no committee multiplication at all. The cost of this choice is real and is the reviewer's point: delivery is not publicly verifiable from the message, and open-mode nonces are owner-dealt and finite.
- **review-fable: key-independent committee nonce pools with ROAST.** Not adopted; it does not fit. The owner knows `x` and `k`, so the owner deals the nonces. The consequence, that more than `f` Byzantine nodes yield the key and not only a double spend, is stated in §6.5 and §10.
- **review-fable: `t = n − f` as the general default.** Adopted for sealed mode only. In open mode a high `t` adds leakage tolerance and no active security, so the default is `f + 1`.
- **review-carbon: verifiable encryption (cgVSS or chunked ElGamal) as the fix for resharing at high `t`.** Not adopted; `t = f + 1` for resharing was chosen. It keeps the design free of class groups and of the order-2 question. The price is that sealed T2 requests cannot survive a rotation.
- **review-carbon: a BFT leader proposal for the anchor.** Not adopted; the leaderless median rule was chosen because a leader adds view changes and a way to burn a request.
- **review-astra: active security for every coalition below `t`.** Met only by setting `t = f + 1`. For `t = n − f` it is declared unmet, not solved.
- **review-astra, on cand-a7e2: a publicly verifiable dealing of plain Shamir shares feeding an existing threshold-signing implementation.** Not adopted, for the same reason as the first item.
- **Merge brief: one identity formula `H(chain, board, X, owner_nonce)` for every request.** Adopted for open mode; sealed mode adds `hd`, for the squat described above.
